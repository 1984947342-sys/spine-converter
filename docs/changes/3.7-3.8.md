# Changes from 3.7 to 3.8

Migrated by `src/migrate/v3_7_v3_8.zig`. [README.md](README.md) defines the classes.

| Main changes |
|---|
| skins become a list |
| curves split into curve c2 c3 c4 |
| `paths` timelines become `path` |
| scale keys default to 1 |
| IK softness |
| skin required bones and constraints |
| linked mesh deform |
| one bone IK on bones that do not inherit rotation or scale |
| two bone IK with the child at the parent origin |

3.7 to 3.8 reports one bone IK on bones that do not inherit rotation, or do not inherit scale while they stretch or compress, because the final 3.8 runtime solves them from the bone world transform after upstream 203a648ae. Editors before 3.8.81, betas included, solve them as 3.7 and so does a two bone IK with the child at the origin of such a parent. A source of such an editor goes down without this loss and reports `ik.beta.approximated` kept within 3.8 or converted up. Both cases are rewritten to a normal proxy bone where [rewrites.md](rewrites.md) allows, else reported. `src/Version.zig` holds the bounds of every editor dated change, see `runtime-changes.md`. The bounds position of the skeleton has no 3.7 field and no runtime poses from it, so dropping it is an editor loss. A runtime skeleton scale of unequal or negative axes scales the columns of the root in the 3.7 editor and the rows in 3.6 and from [ccc5b2f38](https://github.com/EsotericSoftware/spine-runtimes/commit/ccc5b2f38) on, so a root with rotation or shear in its setup or keys reports `skeleton.scale.approximated` of impact control where a 3.7 source goes up or 3.7 is the target. The data cannot carry the runtime scale, see `needs-a-runtime.md`.
