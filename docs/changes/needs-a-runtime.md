# Needs a runtime

Each semantics below changed between runtime versions, and no data of the named target reproduces the old result in general. The converter rewrites every case it can prove exact, see [rewrites.md](rewrites.md), and reports the rest. Into a 4.3 target an entry carries remedy `runtime` when its code is left only by these rows, `Code.needsRuntime` in `src/Report.zig` lists those codes. The project then keeps a runtime patch or changes the rig. A row names the cases that stay reported and the reason at formula level.

| Semantics | Code | Reason |
|---|---|---|
| noRotationOrReflection of 3.5 betas through 3.5.03 | `bone.noRotation.approximated` | 3.5.02 and 3.5.03 betas (eb1e8e794) compute the parent basis times the local matrix times a turn back by the parent angle, which only a 4.3 helper chain with world transform mappings rebuilds, so lower targets keep the report. 3.5.00 and 3.5.01 betas, before eb1e8e794, keep the full parent matrix with its second column negated when reflected and subtract the parent angle from the local rotation; the oracle emulates only the eb1e8e794 formula, so the converter cannot tell the two apart from the version alone without a second editor key, and this formula stays reported |
| relative local scale of 4.0 before 4.0.27 that reaches a bone scale of 0, runs with every mix but scaleY at 0, follows an earlier constraint on the bone or uses a skin bone, or any such scale into 4.0 to 4.2 | `transform.relativeScale.approximated` | `1 + s * k` gives 1 at a bone scale of 0 where every 4.3 copy of a scale skips, the old runtime skips the constraint by its own mix test, and 4.0 to 4.2 have no multiplying local scale |
| two bone IK on a parent whose inherit is not normal, from 4.1 up | `ik.skip.approximated` | 4.2 and 4.3 skip such a constraint before solving; the 4.1 solve places the child through the world matrix of the parent but turns it through its applied local values, a frame mix no normal parent chain reproduces by copying, and a construction from IK probes would need about four helper bones and eight constraints per IK and stays open for stretch and nonuniform parent scale. A child alone is rewritten |
| local absolute transform scale of 3.5 to 4.2 with a bone scale that is keyed through 0 or ends at 0, a scale mix of both signs, a scale mix that reaches 0 on both axes with different keys or beside a floor mark, a source among the constrained bones, or an earlier constraint that can change the applied scale of the bones | `transform.scale.approximated` | the old result 1 - mix + (target + offset) * mix / s has a pole at a bone scale s of 0, so no finite key range fits the reciprocal slider, an earlier constraint with a scale mix, IK stretch or compress, a world rotate or shear, a path or physics makes s depend on a live matrix that keys do not bound, a mix of both signs puts the gate step at a nonzero slider time where one float step, about 1e-7 of that time, is its width, and a source among the constrained bones is overwritten by the reciprocal slider before the multiplying transform reads it |
| physics of 4.2 in 4.3 or of 4.3 in 4.2 | `physics.step.approximated` | the minors integrate physics differently, no data changes the integrator |
| world shearY offset of 3.5 to 4.2 of 180 or more with a partial mix and a source that may reflect | `transform.shearOffset.approximated` | the signed offset rig reads a local rotation that 4.3 derives from world matrices in -180 to 180, the old result adds the whole offset times the mix |
| absolute world shear mix of 3.5 to 4.2 keyed through 0 with a source that is a constrained bone or below one | `transform.shearMix.approximated` | the clamped copy of the shear reads the source after the other mappings changed it, 4.2 reads it once before |
| world constraint result under a later ancestor constraint in 4.3 before 4.3.18 on a bone with shearX in setup or keys, a scale at or below 0 in setup, keys or Bézier controls, or a skin bone | `constraint.order.approximated` | the old `resetWorld` sets `local = 0` on each descendant with `local == update`, so the bone is rebuilt from its pose fields; the restore copies those fields from a clone through a local transform constraint, which has no shearX property, skips a target scale of 0 and cannot follow a skin bone that is inactive in some skins |
| the same reset where another constraint sets the bone locally or reads its local pose, where a later constraint that moves an ancestor is not a transform constraint, may be inactive in a pose or has a skin, or where the earlier constraint is physics | `constraint.order.approximated` | the old rebuild depends on the flag `local == update`, which a local write or a local read through `updateLocalTransform` clears, so the rebuilt pose is the fields at that moment, the result of the local constraints or an earlier world result, and a skipped later constraint never rebuilds; a clone holds only the keyed pose and no constraint data tests that flag |
| mixScaleY of 4.0 and 4.1 before 4.1.18 that other mixes leave 0 around, into 4.1 and 4.2 | `transform.mixScaleY.approximated` | the old runtime scales by mixScaleY * [any other mix is not 0], where the step edge sits at a key time and needs two mixScaleY values at that time, a 4.1 or 4.2 key holds one value per time and interpolates it to the next key, and without sliders nothing else gates the mix |
| mixScaleY of 4.0 and 4.1 before 4.1.18 that other mixes leave 0 around, into 4.3 beside a shear mix with a mixScaleY outside 0 to 1 or a negative scaleY offset, or beside a scale rewrite of the same constraint | `transform.mixScaleY.approximated` | the gated scaleY runs after the shear, and a scale factor (s + (t - s + o) * m) / s below 0 turns the bone axis so that the shear angle differs from the old order, a scale rewrite takes the mixScaleY keys into its own passes that the gate cannot multiply |
| world constraint of 4.2 on a bone with inherit noScale, noScaleOrReflection or noRotationOrReflection with a setup rotation, a rotating constraint, a shear, a reflecting ancestor or a reader other than an always active one bone IK, or in a 4.3 export before 4.3.03 a rotating or scaling constraint, a slider, or a reader that is only an ancestor constraint | `bone.derive.approximated` | 4.2 derives the rotation against the frame of the stale local rotation, poses it against the frame of the derived rotation and drops the parent rotation of noRotationOrReflection, so the bone has one frame for the read and another for the pose, which one 4.3 bone cannot hold; scaleY of 4.2 is the determinant over scaleX, the product with the cosine of the shear, where 4.3 keeps the length of the second column; the old 4.3 runtime derives the local lazily when read, after a later ancestor constraint moved the parent, where 4.2 derives it at once against the old parent |
| applied transform of 4.1 with shear, or with inherit other than normal, read by a recomposing reader or a shear reading local transform, into 4.2 | `bone.applied.approximated` | 4.2 recomposes with `+S` where 4.1 recomposes with `-S`, and no 4.2 constraint negates a value, an absolute local copy blends toward the source, a relative one adds it, a world copy keeps the sign |
| applied transform of 4.1 with shear that varies by key, under a distorted ancestor, or beside a shearing mix, or with inherit other than normal, into 4.3 | `bone.applied.approximated` | 4.3 derives the local scaleY as the length of the second axis, 4.1 applies the determinant over the first axis, the length times the cosine of the live shear, a product of two live values that no constant mapping scale forms, and a non normal bone adds the mode decomposition and the `bone.derive.approximated` pass |
| negative path mix of 3.8 that turns positive on one mix while the other is 0 or below, into 4.0 to 4.2, or with a path constraint bound to a skin | `path.negative.approximated` | 3.8 returns while rotateMix <= 0 and translateMix <= 0 and 4.0 skips only at three mixes of exactly 0, so the pose differs by the negative mixes whenever neither is positive, 4.0 to 4.2 have no slider to gate the mixes by the sign of the live ones and a skin bound constraint would need its gate parts in the skin lists of its own kind |
| bone or IK under a parent whose scale nears 0 | `ik.singular.approximated` `bone.singular.approximated` | the thresholds test the determinant and scale of the live parent world matrix, which constraints and mixing move past any bound the keys give |
| path position on a curve start in 3.5 and 3.6 before 3.6.46 or 3.7 before 3.7.43-beta | `path.start.approximated` | the old runtime evaluates a curve start at parameter 1e-4 or with another tangent, the shift follows the live curve shape and no position offset matches it for every pose |
| absolute local shear mix of 3.6 and 3.7 before 3.7.74-beta | `transform.localShear.approximated` | the old mix shears the local pose in place every frame, the result accumulates over the frames played |
| two bone IK with the child at the parent origin of 3.8.25-beta | `ik.origin.approximated` | the branch is decided by float noise of the live pose |
| relative local transform of 3.8 with a partial rotate mix and target rotation keys past 180 from setup | `transform.rotateRange.approximated` | 3.8 keeps the target rotation modulo 360 around the setup rotation under setup blending and around the previous frame under first blending, so the mix reads a representative that depends on playback history, 4.0 keys hold one absolute angle |
| color Bézier overshooting 0 or 1 of 4.2 in 4.3 | `color.clamp.approximated` | 4.3 clamps each timeline value before it blends by alpha, 4.2 blends the overshoot, keys without the overshoot change every partial alpha |
| IK scaleY volume of 4.3 before 4.3.02 with compress or a factor below 0.7 | `ik.volume.approximated` | the old bounded formula is another function of the live stretch, no IK setting of the final runtime gives it |
| closed constant speed path with negative or large spacing of 4.2 | `path.closed.approximated` | 4.2 keeps a stale segment index from the previous lookup, the result depends on the order of the live positions |
| slider keying deform or sequence of a linked mesh in another slot, 4.3 before 4.3.24 | `slider.linkedMesh.approximated` | 4.3 betas leave the slots of the linked meshes unconstrained, so the slider writes their unconstrained pose, which persists across frames instead of resetting each frame |

## Runtime state

These depend on state the application sets at run time, so no data holds them. They are reported with impact control, the oracle judges them as pose under `ORACLE_FLIP`.

| Semantics | Code | Reason |
|---|---|---|
| skeleton flip or scale set by the application, with offsets, reflections or IK that read it | `bone.flip.approximated` `skeleton.scale.approximated` `transform.offsetFlip.approximated` `path.offsetFlip.approximated` | the flip and the skeleton scale are runtime state, the data cannot see them |
